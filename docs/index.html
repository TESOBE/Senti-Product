TESOBE Senti

Senti watches your APIs, Apps, Services and Pages and suggests security and performance fixes.

TESOBE Senti is a semi-proactive AI agent that runs beside development, staging and production systems. It combines what the running system is doing (logs, metrics, telemetry) with the source code behind it, finds the bugs, slowdowns and security holes that matter most, and proposes, tracks and rescans code fixes.

What Senti looks at

01

Source code

Reads the code behind every page and endpoint that can be reached, public ones first, looking for SQL injection, missing authorisation checks and similar problems. It reads the exact commit each server is running.

02

Logs

One record per event: a request, an error, a retry. Senti groups the lines that describe the same problem, even when their ids, numbers and emails differ, then counts each problem over time. A thousand timeouts become one finding, not a thousand alerts.

03

Metrics

Aggregates over time: call counts, and averages and percentiles of response times. Senti compares the last hours with the hours before, and notices what is getting slower before your users do.

04

Telemetry

System resources: CPU, memory, disk and connections. Senti correlates a slow page, a slow endpoint or a burst of errors with the resource that ran out.

What it does

  • Watches development and running systemsEvery 2 minutes it reads error logs and metrics. It groups log lines that describe the same problem and compares each hour with the hours before, so new or growing problems stand out. This part uses no AI.
  • Finds causesWhen something new has happened, the AI agent reads these figures and the source code of the exact version that is running. Each finding is scored by impact, confidence, effort and trend, with evidence.
  • Reviews code for securityEven where the logs show nothing, it reviews each reachable service for problems such as SQL injection and missing authorisation checks. It also reads SonarCloud's and other security results.
  • Highlights the most importantA web page and digest show the most important suggestions at a time. Senti learns from the team's ratings and dismissals.
  • Fixes, with a person in chargeOn request, the agent edits the code, runs tests and stages the change. The developer can change the commit message. Creating issues and pull requests are natural extensions.

How it works

Plain code collects the logs and numbers. The AI analyst reads them with your source code, only when something is new. A person decides on every change.

Requirements in a company environment

AreaWhat is needed
ServerOne Linux host or container with Python 3.11+, git and Claude Code. Data is kept in local SQLite files.
NetworkOutbound HTTPS to the watched systems (or their Prometheus and Loki), the identity provider and the AI model. Inbound only to the Senti web page.
Monitored systemAny service with its logs in Loki and its metrics in Prometheus. Configured for OBP: OBP-API's own log cache (Redis) and Telemetry, and its apps. Custom connectors are possible.
AccessIts own machine identity (OAuth2 client credentials from the company's OpenID Connect provider), with read-only Scopes. No user account. Read access to Prometheus and Loki.
Source codeA checkout of the running code on the same host, read with git.
AI modelClaude Code with an Anthropic account or API key.
Data to the modelLog patterns with samples, metrics and source code. Sensitive values are masked in the logs, but the model provider must be approved for source code and log data.
Cost controlA Claude Max plan, or a spending cap per run. Analysis runs only when something is new.
IsolationRuns as its own operating system user. The agent may only run Senti's commands and read-only git, and write to its work folder.
Web pageRuns on localhost, or behind the company's authenticating reverse proxy.
PeopleSomeone to set up access to the logs and telemetry; developers who own the code and decide on fixes.
